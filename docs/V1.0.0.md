# v1.0.0 Product Contract

## Purpose

v1.0.0 establishes the portable Windows browser/account workspace without introducing proxy infrastructure.

## Included

- Windows-only Tauri v2 application.
- EXE-relative portable workspace initialization.
- Persistent Browser Profiles with independent Thorium `User Data` directories.
- Portable Thorium installation/update/version management.
- Generic account management with GitHub and Microsoft presets.
- Encrypted password/secret vault.
- TOTP/HOTP and QR import.
- Recovery-code management.
- Clipboard timeout protection.
- Vault locking.
- Profile timezone and locale controls using supported browser mechanisms.
- Windows Job Object process supervision.
- Backup/recovery/diagnostics.
- Windows CI and portable EXE release pipeline.

## Excluded

v1.0.0 must not add:

- Xray-core;
- proxy pools;
- proxy subscriptions;
- SOCKS/VLESS/VMess/Trojan/Reality routing;
- network-IP rotation;
- WFP-based proxy leak protection;
- automated account registration;
- CAPTCHA handling;
- account farming or automated posting;
- randomized fingerprint spoofing.

## Core data relationship

```text
Workspace
  |
  +-- Thorium Installations
  |
  +-- Browser Profiles
       |
       +-- independent User Data
       +-- timezone / locale
       +-- startup URLs
       +-- Accounts
            |
            +-- metadata
            +-- encrypted password
            +-- second factors
            +-- recovery codes
```

## Release acceptance

A clean Windows user must be able to:

1. run the portable EXE from a writable directory;
2. initialize and unlock the Vault;
3. download/install portable Thorium;
4. create multiple browser profiles;
5. create multiple account records per profile;
6. import and use TOTP safely;
7. launch multiple independent Thorium profiles concurrently;
8. restart the manager without data loss;
9. build the exact same project successfully through GitHub Actions.

## Future compatibility

The persistence model should permit a future Browser Profile to reference a network route/proxy ID, but v1.0.0 should not implement or expose that subsystem. Avoid speculative abstractions beyond the small stable extension point needed for future schema compatibility.
